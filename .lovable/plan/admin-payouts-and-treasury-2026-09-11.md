# Admin payouts and treasury

## What I’ll build

- Add an admin payout-history view grouped by settled market, showing each winner, stake, payout amount, payout state, payment date, and transaction reference.
- Add an admin treasury view showing the configured treasury address, network, live balance, total queued payouts, and whether automatic payouts are available.
- Add a “Pay pending winners” action that retries queued or failed payouts from the treasury and refreshes the balance and history.
- Add a “Fund treasury” flow that opens Nimiq Pay and sends the entered NIM amount from the connected admin wallet to the treasury address.
- Organize the admin console into clear Markets, Treasury, and Payouts views without changing player-facing game rules.

## Technical details

- Keep all payout and treasury reads behind authenticated admin-only server functions.
- Reuse the existing on-chain treasury balance reader, Nimiq Pay transaction method, and payout retry driver.
- Use the existing settlement, prediction entry, profile, and prediction records; no database schema change is needed.
- Return only display-safe payout data to the admin screen and keep wallet credentials server-side.
- Document every required environment variable in a safe example file. The managed `.env` file is generated by Lovable Cloud and must not contain treasury passphrases; secret values remain in encrypted runtime configuration.
- Correct the existing five-item bottom navigation layout and verify the admin experience at the current mobile size and desktop size.

## Validation

- Check TypeScript and the preview build.
- Verify admin access gating and the new tabs in the live preview.
- Confirm empty, pending, paid, and unavailable-treasury states render without page errors.
